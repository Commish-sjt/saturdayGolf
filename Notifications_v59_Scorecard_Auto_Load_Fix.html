Notifications Tool — Functional Specification

Document Version 1.1 · Updated November 8, 2026 · Application baseline: Notifications v59

Purpose. The Notifications tool prepares pre-round and post-round communications for the Saturday Golf League using Squabbit CSV exports. It also supports payout review and publishing event information to Google Sheets.

1. System Overview

  • Frontend: Browser-based HTML and JavaScript.
  • Input: Manually exported Squabbit CSV files.
  • Processing: CSV data is processed in the browser.
  • Backend: Google Apps Script web application.
  • Storage: Google Sheets.
  • Hosting: GitHub Pages.
  • Email: Currently prepared for administrator review and copying/sending; future Gmail integration must require approval before sending.

2. Administrator Workflow

  1. Import CSV & tee sheet: Load the upcoming-round planning export and review the roster and tee sheet.
  2. Game information: Review format, buy-in, payouts, contests, teams, and scoring settings.
  3. Pre-round email: Generate and review the upcoming-round email.
  4. Results & post-round email: Import the completed-results export and review winners, payouts, and contests.
  5. Scorecards: Use the pre-round planning CSV from Step 1 before the round; after the round, the completed-results CSV from Step 4 replaces it automatically.
  6. Publish to Google Sheets: Test the connection if needed and publish the current event version.

The administrator must be able to move between Pre-round and Post-round without a mode-navigation check incorrectly blocking the selection. Multiple exports may be loaded as event information becomes available during the week.

3. Input Data

Squabbit is the source of truth. CSV data may include event name/date, course, format, players, tee times, tee assignments, teams, handicap information, playing handicaps, quotas, scores, results, payouts, CTP winners, low gross, and birdies or better. Missing values must not be invented. The tool should support replacing an earlier export with a newer version.

4. Pre-round Email

Subject and introduction

Subject format: Saturday Golf, [Date] @ [Course]. The body introduces the course and event without generic openings such as “Hey everyone” or “Here's the lineup.”

Teams and tee sheet

  • When teams exist, count them and display a numbered list, for example Teams (3).
  • Display each team name once; do not repeat player names in the team list.
  • Omit the Teams section for individual formats.
  • Sort tee times chronologically and list players beneath their tee time.
  • Display tee assignments as Player Name (White).

Handicap display

  • Best Ball: One “Strokes Below” heading; show each player's Squabbit round Playing Handicap in parentheses. Do not substitute Handicap Index.
  • Quota / Team Quota: One “Quotas Below” heading; show each player's quota in parentheses.
  • Quota formula: 36 − Playing Handicap. A +3 Playing Handicap produces a quota of 39.
  • Do not repeat the handicap heading for each tee-time group.

Other game information

  • Show buy-in before the format line.
  • When net scoring is enabled, show: “Scoring: Net Scores — 90%”.
  • Closest-to-Pin wording: “Closest to Pin: Validate with Par”.
  • Include relevant game information, payouts, and contests in the applicable workflow review steps.

5. Post-round Email

Registration reminder

Begin with: Reminder - Register for next week's round in Squabbit. The administrator can enter next week's tournament URL and a display label/date. The date/label must be the clickable link text. If the URL is blank or invalid, do not create a broken hyperlink.

Results and presentation order

  1. Registration reminder and clickable link (when supplied).
  2. Game format and description (for example, Team Quota / Two Man Teams).
  3. Game results and payouts.
  4. Closest to the Pin.
  5. Low Gross Round.
  6. Birdies or Better.

Do not display a separate “Today's Results” heading.

Game results filtering

  • For team games, show only teams receiving a game payout.
  • For individual games, show only players receiving a game payout.
  • List paid finishers in finishing order, with score and payout.
  • Do not remove separate contest winners from the CTP, Low Gross, or Birdies or Better sections merely because they did not win the main game payout.

Contests

  • Closest to the Pin: Show hole, winner, and payout.
  • Low Gross Round: Show winner and gross score.
  • Birdies or Better: Show player names and birdie/eagle-or-better holes.

7. Payout Calculations and Validation

  • Calculate and display game payouts; compare their total with the total pot.
  • Keep CTP payouts separate from the main game payout total.
  • Retain the established round-down behavior where applicable.
  • Do not add rounding differences to CTP winners.
  • Make missing payouts, over-allocation, and unallocated money visible to the administrator.
  • Payouts and contests should be available for review in both Step 2 and Step 3.

8. Google Sheets Publishing

The tool communicates with the league's Google Apps Script web application. Known spreadsheet tabs include Players, Events, Event Versions, Tee Sheet, Pre-Round, Results, and Event Detail.

  • Allow connection testing.
  • Publish only when the administrator presses the publish control.
  • Support event versions and preserve event history.
  • Publish tee sheet, pre-round, results, and event detail data as applicable.
  • Final results publication marks the event Completed.
  • Display a clear success or failure message.

9. Email Generation and Approval

The current workflow prepares email content for administrator review and copying into the regular email app. The planned Gmail integration may prepare and send messages, but must require explicit administrator approval before sending. No automatic send without approval.

10. User Interface and Error Handling

  • Browser-based, responsive desktop/mobile layout.
  • Clearly separated workflow steps and Pre-round/Post-round modes.
  • Readable email previews and clear copy/send controls.
  • Understandable errors for missing CSVs, wrong export type, missing event data, unrecognized players/teams, incomplete payout data, invalid registration URLs, and Google Sheets connection or publishing failures.
  • Preserve entered event information when switching workflow sections.

11. Data Integrity and Safety

  • Squabbit remains the source of truth for event information.
  • Do not silently alter player names, scores, or payout values.
  • Do not fabricate missing information.
  • Preserve published event versions.
  • Require administrator approval before email sending.

12. Acceptance Checklist

Pre-round

  • CSV imports and event details are correct.
  • Team count and numbered list are correct, with no duplicate roster.
  • Tee times sort correctly and tee assignments use “Player Name (White)”.
  • Best Ball Playing HCP and Quota values use the correct source/formula.
  • Handicap heading appears once; individual formats omit Teams.
  • Buy-in, net scoring, CTP wording, payouts, and contests display correctly.

Post-round

  • Registration reminder appears and date text links to the entered URL.
  • “Today's Results” heading is absent.
  • Format and description are correct.
  • Only paid teams or players appear in main game results.
  • CTP, Low Gross, and Birdies or Better remain correctly displayed.
  • Payout totals and rounding behavior are correct.

Publishing and email safety

  • Google Sheets connection and publishing work.
  • Correct event version is recorded.
  • Final publishing marks the event Completed.
  • No email is sent without administrator approval.

13. Items Requiring Verification

  1. Exact mapping of all Squabbit CSV columns.
  2. Complete post-round payout behavior for every supported format.
  3. Exact Step 2 and Step 3 display behavior for payouts and contests.
  4. Gmail integration and approval implementation.
  5. Persistence of registration-link fields after reopening the tool.
  6. Detailed Ryder Cup email presentation and scoring.
  7. Validation behavior for incomplete or inconsistent Squabbit data.

14. Version Management

Each update should start from the latest approved HTML, preserve working behavior, increment the version number, and include a complete downloadable file with a concise change summary. This specification is an operational baseline; items listed under “Items Requiring Verification” are not claims of completed functionality.

Squabbit FAQ — Quick Help

Short answers for the most common Saturday Golf tasks in Squabbit. Menu names can vary slightly by device or app version.

How do I register for the upcoming Saturday round?
  1. Open the Saturday Golf League in Squabbit.
  2. Choose the upcoming Saturday event.
  3. Open the event and use its registration option to sign up.

Players should register for the next round by Monday.

How do I create the event for next Saturday?
Create a new event in the Saturday Golf League for the next Saturday round. Confirm the event date, course, and other event details before sharing it with players. The weekly event is separate from the permanent league link.
Which Squabbit CSV should I download for this tool?
  • Before the round: use the upcoming event’s planning/export CSV with the roster and tee-sheet information available.
  • After the round: use the completed event’s results CSV after scores have been entered.

Import the pre-round file in Step 1 and the completed-results file in Step 4. Do not use the results file to prepare Friday’s email.

Where can I find the tee times and player groups?
Open the upcoming event in Squabbit and review its tee times or tee sheet. In this tool, import the pre-round planning CSV, then continue to Step 2 to review the groups and copy the tee-sheet text.
How do players enter scores after the round?
Open the correct event in Squabbit and use the event’s score-entry or scorecard feature to enter the round’s scores. Check that scores are complete before downloading the completed-results CSV for Step 4.
Where do I find completed results?
Open the completed event in Squabbit to review its results. For the post-round email, download the completed-results CSV and import it in Step 4 of this tool.
What if I cannot see the upcoming event?
First, make sure you opened the Saturday Golf League link and not an old event link. Then check the event list for the correct Saturday date. If the event has not been created yet, contact the league administrator.
